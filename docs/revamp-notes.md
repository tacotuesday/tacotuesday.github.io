# Portfolio revamp audit

Audited on 2026-08-25 before migration work began.

## Repository and publishing

- The production site is a GitHub Pages user site built from a customized Priam Jekyll theme on `main`.
- No GitHub Actions workflow existed. Deployment depended on GitHub Pages' legacy Jekyll build behavior.
- The repository had uncommitted edits in the Ruby dependency files and several Jekyll settings/templates, plus an untracked `AGENTS.md`. These edits remove emoji labels and add more specific professional copy. The Astro migration preserves the useful identity and link details while superseding the old runtime files.
- Analytics ID `G-0S2P05DJMR` was already configured. It is retained as an explicit, optional site setting rather than replaced or supplemented.
- Existing outbound identity links worth retaining are GitHub (`https://github.com/tacotuesday`) and LinkedIn (`https://www.linkedin.com/in/graftoncook`).
- Existing real assets worth retaining are the two professional headshots and the screenshots/charts associated with the four learning projects.

## Existing public URLs

The following routes were generated by the checked-in Jekyll configuration and the last local build. They are migration obligations even when they were not linked in navigation:

- `/`, `/404.html`, `/feed.xml`, `/sitemap.xml`
- `/about/`, `/contact/`, `/elements/`, `/tags/`
- `/blog/`, `/projects/`, `/gallery/`, `/videos/`
- `/projects/building-an-aws-batch-pipeline`
- `/projects/building-a-realtime-data-pipeline`
- `/projects/the-color-of-success`
- `/projects/unlocking-customer-value`
- `/gallery/hobby`, `/gallery/hawaii`, `/gallery/california`, `/gallery/memories`
- `/videos/boosting-traffic-and-engaging-your-audience`

GitHub Pages also serves trailing-slash and `.html` variants for generated static files. Redirect stubs therefore cover both extensionless and `.html` forms where the old collection output used `.html` files.

## Content assessment

- Four substantive but tutorial-oriented projects are worth retaining as an honest learning archive: two AWS pipeline exercises, a synthetic customer-segmentation analysis, and an advertising color experiment.
- The project Markdown contains useful screenshots and repository links, but it is structured as chronological learning narratives and includes over-strong or generic claims. The archive presentation needs concise context labels, corrected image markup, and preserved source links without treating the work as current case studies.
- The gallery, video, elements, tags, contact form, demo testimonials, and newsletter are theme fixtures or unrelated to the new professional positioning. Their inbound routes should remain usable through redirects or archive notices, not remain in primary navigation.
- There are no existing posts in `_posts`, so the old `/blog/` page and RSS feed are empty.

## Visual and technical problems

- The homepage is dominated by a `#100DaysOfCode` stock banner and generic portfolio cards rather than a clear statement of practice.
- Boilerplate claims, emoji navigation, fake theme testimonials, generic contact copy, and theme attribution undermine credibility.
- Typography, rounded-card repetition, stock photography, and loose hierarchy make the site look like a tutorial template rather than a technical editorial portfolio.
- Several retained images use generic alt text; some Markdown/HTML combinations are malformed or difficult to maintain.
- Canonical URLs are not configured because `_config.yml` leaves `url` blank. Social metadata, structured data, and a branded social preview are missing or incomplete.
- The site has no typed content model, draft filtering contract, production-placeholder validation, automated accessibility tests, responsive route tests, broken-link checks, or performance budgets.
- The public footer showed a stale fixed year and third-party theme credit. The site also shipped broad theme JavaScript and integrations even when their features were unused.

## Migration decisions

- Migrate to Astro 6 static output with strict TypeScript, MDX, and typed collections for projects, writing, and Lab entries.
- Keep showcase fixtures outside production content collections and exclude `/showcase/` from robots, RSS, and sitemap output.
- Move the four project narratives into `/archive/` and use static redirects for their original `/projects/...` URLs. Preserve hidden legacy destinations with explicit archive labeling rather than presenting fixture content as current work.
- Retain GitHub, LinkedIn, RSS, and the existing analytics identifier. Remove the public form, theme testimonials, newsletter, stock hero, and unused theme integrations.
